# 找图、截图、挑图

目标：**每个节点一张真实的图**，图下写明来源。宁可用最接近的真实画面并注明，也不画假界面。

## 1. 先盘点已有素材（最快）

按这个顺序找，通常能覆盖七成节点：

1. **仓库各分支里的图**（不切分支就能列）：
   ```bash
   for b in $(git for-each-ref --format='%(refname:short)' refs/heads); do
     git ls-tree -r -l "$b" | awk -v b="$b" '{print b"\t"$4"\t"$5}' | grep -E '\.(png|gif|jpe?g|webp)$'
   done | sort -t$'\t' -k3 -u > imglist.tsv
   ```
   这一步在 iCloud 等慢盘上可能要几分钟，放后台跑。取图用 `git show 分支:路径 > raw/文件`。
2. **验收与测试证据目录**：设备截屏、手机 adb 截图、自动化测试截图（常在备份目录、`evidence/`、`~/.cache/...`）。
3. **产品说明、说明书、汇报材料里的配图**。
4. **外观渲染**：只用于根节点、硬件节点。

全部拷到一个草稿目录，用 `scripts/contact_sheet.py` 拼成对照表一次看完。文件名常常对不上内容（比如 `companion.png` 其实是卡片页），**以看到的画面为准**，再放大看存疑的几张。

## 2. 缺的状态，从原型里截

**canvas 原型**（固件模拟器、小游戏）：

1. `python3 scripts/capture_server.py <原型根目录> <输出目录>` 起本地服务（`file://` 打开时浏览器面板可能只给静态快照，脚本不跑）。
2. 在浏览器里打开原型，读它的源码找到状态对象和 `render()`。顶层 `const state` 在页面里可直接访问。
3. 在页面里逐个状态改变量、调 `render()`、`canvas.toDataURL()` 后 `fetch('/save', …)` 存图。需要动图就连续存十几帧，再用 `build_assets.py` 的 `gif` 操作拼。
4. 把渲染倍率调高（如 3×）再截，图更清楚。

**DOM 原型 / 网页 / 场景实验室**：写一份 `shots.json`，用 `scripts/shoot.py` 截元素或整页（点按钮切场景、执行一段 JS 改状态，都在 steps 里写）。

需要先构建才能打开的页面，**拷到草稿目录里构建**，不要在仓库里生成未跟踪文件。

## 3. 竞品图从网上找

- 先抓调研报告附录里已经列出的来源页（官网产品页、评测文章、帮助文档），再做补充搜索。
- 每张图记录：画面内容、来源页 URL、图片 URL、日期，写进 `assets[key].c` 和 `u`。
- 下载到全新的空目录（不可信内容），只收图片文件。
- 优先选能看清「功能场景」的图：屏幕特写、按键特写、App 关键页（转写、摘要、待办）。纯外观图只给产品节点。
- 无屏产品的「场景」就是按键和灯：产品图 + App 截图即可，图说里写清楚。

## 4. 挑图规则

- 节点对应的画面就在图里：节点讲「卡片长按菜单」，图里就得有那个菜单。
- 叶子没有专门画面时，用父节点或兄弟节点里最能说明它的那张，图说照实写。
- 用替代图时（比如没有该应用截图，用同类原型），图说写「××暂无截图，用此示意」，来源类型标 `td` 或 `sm`。
- 状态要对得上：只在预览里跑过的功能，不要配实机截图冒充。
- 一张图里只有一小块是重点（屏幕上的录音图标、待办列表），给它加 `focus` 细节框，或用 `crop` 操作单独裁一张。

## 5. 压缩

写一份 recipe.json，用 `scripts/build_assets.py` 一次产出：手机截图压到 720 px 高的 WebP（约 20–40 KB），横图最宽 900–1600 px，已有 GIF 原样拷贝。整套素材控制在 10 MB 以内（Artifact 单页 16 MB 上限，文件另算，但越小打开越快）。
